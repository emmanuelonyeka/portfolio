01 Hospitality · Brand simulation · Self-initiated

Lumière — A Two-Michelin-Star Brand World

Not a restaurant page — a complete brand simulation. A multi-page experience for a fictional two-Michelin-star Paris restaurant, engineered with the depth of a real client build: a full menu system, a reservation flow, three signature experience tiers, and the kind of editorial polish that a real luxury hospitality brand would actually ship.

3 Pages built
(home, reservation, legal)
8 Menu categories
with filterable views
3 Experience tiers
with deep-link routing
100% Built without
a single backend call

The Brief

A self-initiated brand build with one rule: don't make a "demo." Build it like a real two-Michelin-star Paris restaurant would build it — full menu, full reservation flow, full editorial story, full press coverage panel, real opening hours, real address, real recognition badges. If a hospitality group dropped their content in tomorrow, the site should be ready to ship.

The Challenge

The reservation system. Every other section is a styling and content problem — the booking is an engineering problem. A real reservation flow needs a database to hold availability, server logic to validate party sizes against table capacity, and an API to commit the booking. I had none of those. The flow still had to feel real: take the date, the party size, the time slot, and respond with the confidence of a system that knows what's actually available.

I spent over 48 hours drafting the logic on paper before writing a line of code — mapping every state the booking could be in, every edge case (party size vs. table capacity, lead time windows, blackout dates, the 15-minute grace period before the table releases), and how each field should react to changes in the others. By the time I started coding, I knew exactly what I was building.

The Approach

A pure-JavaScript state machine driving the reservation form, with availability rules in a config object that mimics what a real restaurant manager would enter: opening hours, table-size buckets, time-slot intervals, blackout dates. The form validates progressively, surfaces errors inline, and updates available slots live as the user changes inputs — the same UX patterns a backend-driven booking would use, just with the rules running locally.

The menu system is its own piece of architecture: eight filterable categories (Starters through Wines & Champagne), each with dietary tags (V/VE/GF), category-aware images, EUR pricing, and a "Show All" master view. The three signature experiences (Tasting Menu / Wine Pairing / Private Dining) deep-link straight into the reservation page with URL parameters — ?experience=tasting#booking — so the user lands pre-routed to the right flow.

Brand-wise: a candle-lit palette, a single distinctive serif for the wordmark, motion timed to feel weighted rather than eager — the way a maître d' moves, not a notification. A complete fictional press world (Michelin badges, World's 50 Best ranking, full chef biography, NYT-style editorial pull-quote) built with the same attention to detail a real luxury brand would demand.

Built with

  • HTML5 — semantic structure, full SEO & Open Graph metadata, schema-aware
  • CSS3 — multi-page design system, custom animations, responsive across all breakpoints
  • JavaScript — state machine, form validation, menu filtering, deep-link routing, gallery filters
  • Multi-page architecture — index.html, reservation.html, legal.html

What I learned

That two days of thinking saves two weeks of rewriting. The booking system shipped close to first draft because the logic was settled before the code started. It's a discipline I now apply to every interface I build — structure on paper before structure in the editor.

And that scope is a craft decision, not a constraint. Choosing to build the full brand world — not a stripped-down sample — is what makes this site read as something a real restaurant could deploy. Anyone can ship a homepage. Shipping the system is what changes the conversation.

02 Real estate · In progress · Self-initiated

PrimeNest Realty — Luxury Property Platform

A high-end real estate interface focused on confident hierarchy, structured property discovery, and the kind of trust signals Nigerian buyers look for when shopping at the upper end of the market.

The Brief

A self-initiated demo aimed at the Nigerian luxury property market. The goal: an interface that signals premium on the first impression — before the visitor reads a word — and gives them an obvious next action whether they're buying, renting, or shopping for a short let.

The Challenge

Real estate sites tend to drown buyers in filters. The risk was building yet another search form that feels like a tax return. I needed the property search to feel like a concierge — quick to scan, obvious where to start, confident in what it surfaces — without sacrificing the filtering depth a real listing site needs.

The Approach

A three-tab search bar (Buy / Rent / Short Let) sits floating just below the hero, half-overlapping it — visually saying "start here" before the user has to think. Each tab loads the right filter set without a page jump. Featured properties below are presented as confident editorial cards, not a dense grid, to keep the premium tone consistent.

Color-wise, a deep navy and warm gold pairing — conservative, trust-forward, not trendy. The kind of palette that ages well across rebrands.

Built with

  • HTML5 — semantic structure for SEO and accessibility
  • CSS3 — custom layouts, hover states, mobile-first responsive
  • JavaScript — tab switching, filter logic, smooth scroll

What I learned

That confident hierarchy beats clever features. Removing options and trusting one clear path through the page made the site feel more capable, not less. I now design every layout around the question: "what's the one thing this visitor should do next?"

04. How I Work

A simple, honest process. No jargon, no surprise milestones — you'll always know exactly where your project is and what's coming next.

    Discovery

    We talk through what you're building, who it's for, and what success looks like — usually in a 30–45 minute call. By the end, we both know the scope, the timeline, and the price. No fixed proposals before I understand the work.

    You get: written project brief & quote

  4. 04

    Launch & Handover

    We deploy to your domain, hook up analytics, and run final checks across devices. You get the full source, a short walkthrough of how to update content, and (depending on the package) up to 30 days of post-launch support for anything that comes up.

    You get: live site, source code, content guide

What I Believe

A few principles that shape how I work — and what you can expect when we build something together.

01

Consistency over talent

I'm building this entire portfolio with HTML, CSS, and JavaScript — not because I think those are the only tools that matter, but because I believe in being excellent with what you have before reaching for what's next. Showing up daily beats showing off occasionally.

02

Think before you type

The best engineering happens on paper. I spent two days planning the Lumière booking system before writing a line of code — and it shipped close to first draft. Slow planning makes fast execution.

03

Craft is in the details

Anyone can ship a site that works. The difference between a working site and a memorable one lives in the small things: a hover state that feels considered, motion that respects the user, spacing that breathes. I obsess over those.

04

Honest scope, honest price

I'd rather quote you a real number for real work than win the project on a vague promise and invoice you twice. If something is outside scope, I'll say so. If it's inside scope, it's done.
